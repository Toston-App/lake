## Why this matters

OAuth (plan 002) covers interactive connectors such as Claude.ai, ChatGPT and
Grok's app. Some callers can only send a **static header**: the xAI API's
remote-MCP tool (`server_url` plus headers), CI scripts, self-hosted agents, and
CLI configs on headless machines. A personal access token (PAT) lets a user mint
a revocable, scoped token in Toston and paste it as `Authorization: Bearer tsk_…`.

If the maintainer answers decision D2 in `plans/README.md` with "OAuth only",
mark this plan REJECTED instead.

## Steps

### Step 1: Model and migration

`models/api_token.py`, class `ApiToken(Base)`:
- `id` Integer PK; `owner_id` FK `user.id` with `ondelete="CASCADE"`, indexed; `name` String(100), not null
- `token_hash` String(64), unique, indexed: the **SHA-256 hex** of the full token. The plaintext is never stored.
- `prefix` String(12): the first 12 characters (`tsk_` plus 8), shown in the UI so users can tell tokens apart.
- `scope` String(10), not null, default `"write"`: either `"read"` or `"write"`.
- `created_at` DateTime(tz) with server default now; `last_used_at` DateTime(tz) nullable; `revoked_at` DateTime(tz) nullable; `expires_at` DateTime(tz) nullable.

Add `api_tokens = relationship("ApiToken", back_populates="owner", cascade="all, delete-orphan")` on `User`.
Import the model in `models/__init__.py` and `db/base.py`. Then generate the migration. **Open it and check** that it
creates only `apitoken` (or whatever table name `Base` derives) with the unique index on `token_hash`,
and doesn't touch other tables. Delete any unrelated autogenerated operations.

**Verify**: `alembic upgrade head` → exit 0, then `alembic downgrade -1 && alembic upgrade head` → exit 0.

### Step 2: The service, `services/api_tokens.py`

- `generate() -> tuple[str, str]`: `plaintext = "tsk_" + secrets.token_urlsafe(32)` and returns `(plaintext, sha256_hex(plaintext))`.
- `async create_token(db, user, name, scope, expires_in_days: int | None) -> tuple[ApiToken, str]`: raise `ServiceError` (status 409) if the user already has `API_TOKENS_MAX_PER_USER` active tokens. Return the plaintext **once**.
- `async list_tokens(db, user)`: the user's tokens that are not revoked, newest first.
- `async revoke_token(db, user, token_id)`: set `revoked_at`. A token belonging to another user raises a not-found `ServiceError` (404). Follow `services/ownership.py` if it has a helper for this.
- `async resolve(db, plaintext) -> ApiToken | None`: look up by hash and reject revoked or expired tokens. Update `last_used_at` at most once a minute, to avoid a write per call.

### Step 3: Endpoints, `api/api_v1/endpoints/api_tokens.py`, mounted at `/api-tokens`

- `POST /api-tokens` with body `{name, scope: "read"|"write", expires_in_days?: 1..365}` → `201 {id, name, prefix, scope, created_at, expires_at, token}`. `token` is the plaintext, returned only here.
- `GET /api-tokens` → a list without `token` and without `token_hash`.
- `DELETE /api-tokens/{id}` → 204.
- All three use `Depends(deps.get_current_active_user)`. Creating tokens must require an interactive session: reject callers whose bearer is itself a PAT. That holds automatically, because `get_current_user` doesn't accept PATs. Add a test proving it.
- Call `enrich_event` with `operation={"type": "api_token_create"|...}` and **never** include the token in the event.

### Step 4: PAT branch in `mcp_server/auth.py`

In `resolve_user_id`, before the OAuth path:
```python
if token.startswith("tsk_"):
    async with async_session() as db:
        record = await api_tokens.resolve(db, token)
        if record is None:
            return None, "invalid_token"
        user = await crud.user.get(db, id=record.owner_id)
        ...  # same active check as the OAuth path
        return user.id, None   # and expose record.scope, see below
```
Scope enforcement: change the return value to a small dataclass
`AuthResult(user_id, error, scope: Literal["read","write"] = "write")`, update the middleware to put
`scope` into `scope["state"]["toston_token_scope"]`, and in `mcp_server/server.py`'s call handler
refuse any tool whose `McpTool.read_only` is false when the scope is `"read"`. Return `isError=True`
with the message `"This token is read-only."`. OAuth tokens get `"write"`. Update the plan 002 tests that
patch `resolve_user_id` to return the new dataclass.

### Step 5: Tests

`tests/api/test_api_tokens.py` (DB-backed, using the `client` and `test_user` fixtures from `tests/conftest.py`):
1. create → 201, and the response contains `token` starting with `tsk_`; the DB row's `token_hash` ≠ the token and equals `sha256(token)`.
2. list → no `token` or `token_hash` keys.
3. revoke → 204, and the token disappears from the list.
4. revoking another user's token → 404.
5. the 11th active token → 409.
6. a PAT used as the bearer on `GET /api/v1/accounts/` → 401, because PATs don't work on the REST API.

`tests/mcp_server/test_pat_auth.py` (mocking style, as in plan 002's `test_http.py`):
7. a valid write PAT → `tools/call create_expense` reaches `call_tool`.
8. a read PAT → `tools/call create_expense` gives `isError` with "read-only", and `list_accounts` works.
9. a revoked or expired PAT → 401.
10. the plaintext never appears in captured logs (`caplog`) during a full call.

## Maintenance notes

- PATs are long-lived bearer secrets. If GitHub secret scanning partnership or similar is ever wanted, the `tsk_` prefix makes them detectable.
- Review focus: hashing at rest, plaintext returned exactly once, no token in logs or wide events, and read scope enforced server-side.
- Follow-up (UI repo): an "AI connections" settings page listing PATs and Clerk OAuth grants, with revoke buttons.
